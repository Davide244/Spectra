# What professionals reject about Roblox

This document is a guardrail list. It records what professional and semi-professional game developers (people who shipped on Unity/Unreal/Godot, studios running Roblox games as businesses, experienced solo developers) actually say drives them off Roblox or keeps them from ever committing to it, and it maps each complaint to the Spectra stance that avoids it. It is the counterpart to `roblox-onboarding.md`: that document courts the Roblox developer by meeting their habits; this one lists what must never be replicated while doing so.

**Sourcing.** Compiled August 2026 from a web research sweep: DevForum feature-request and bug threads (with ages and like-counts, because a request open for seven years is itself evidence), studio postmortems and interviews (Uplift Games, Deepwoken/Rogue Lineage, BedWars, World // Zero, Toilet Tower Defense), journalism (People Make Games 2021, Vice, 404 Media), analyst work (Naavik, GameDiscoverCo, Deconstructor of Fun), and the community-tooling ecosystem itself. Every claim was recency-checked against what Roblox shipped through mid-2026, so this list does not attack already-fixed problems; where Roblox did fix something, the shape of the fix (late, opt-in, partial, migration-forcing) is usually itself instructive. Thread titles are given so claims can be found; treat specific dates and figures as reported, not re-verified here.

**How to read the statuses.** *Still true* means the complaint stands as of mid-2026. *Partially addressed* means Roblox shipped something that chips at it, with the residue noted. A complaint that took Roblox seven years to answer is listed even when answered, because the seven years are the lesson.

## 0. The pattern, stated as law

Nearly every complaint below has one of two shapes.

**Shape one: the platform keeps the structured layer for itself and hands developers an unstructured escape hatch.** A native signal type user code cannot construct. A native character controller user code cannot rewrite. Automatic replication user code cannot tune, next to raw remotes that provide nothing. No entity model, next to free-floating scripts. Every one of these spawned a community-library genre that is really a bug report: GoodSignal, Chickynoid, Zap, Knit, Matter.

**Shape two: the platform owns ground that shifts under shipped games.** One engine version for everyone, weekly, unpinnable. Assets that live in a cloud with a moderation queue and can be retroactively muted. Formats nobody else can read. Terms that change and reach backward.

Spectra therefore commits to three laws, from which the rest of this document derives:

1. **Every abstraction the engine uses internally is either replaceable through a seam or constructible from userland.** The engine may ship a character mover, a signal type, an entity model; it may never ship one that user code cannot rebuild or swap. (The `CharacterMover`, rewritable in Luau with no engine C# changes, is the existing proof of the rule.)
2. **Nothing a developer ships changes underneath them without their consent.** Engine versions are pinned by the game, formats carry explicit version contracts (`MinimumReadableMapVersion`, `ROADMAP.md` F2), deprecations never auto-migrate content, and unknown data in a map survives a round trip (P2's pinned invariant).
3. **Local files, text where authored, no account required.** The entire workflow (author, build, test, version, ship) must function on a machine with no network, under plain git. Anything cloud-side is additive, never gating.

## 1. Source of truth and tooling: the Rojo lesson

**What professionals say.** The single most repeated complaint across every source: the game lives in a binary place file, so git, diff, branch, review, and CI are impossible without third-party tooling. Rojo's own tagline is the complaint inverted ("enables Roblox developers to use professional-grade software engineering tools"); Adopt Me's team built a predecessor (Rosync) themselves because "many of our favorite tools don't work within Roblox Studio". Team Create, the only first-party collaboration model, is last-write-wins co-editing of the production place; a critical 2022 bug thread documents the Drafts+Packages merge dialog silently corrupting two developers' work. There was no headless engine, so CI meant booting Studio in a Windows VM (run-in-roblox) until the Open Cloud Luau Execution API arrived in late 2024, still rate-limited and without DataStore access. There is no first-party package manager (Wally is built and hosted by a game studio). Every asset (mesh, audio, texture) must round-trip through Roblox's cloud, receive an opaque immutable ID, and pass a moderation queue that developers report holding audio for weeks; a whole tool genre (Tarmac, Asphalt, Tungsten) exists just to map source files to asset IDs. Studio itself is mandatory, online, and force-auto-updating. Roblox's first-party Script Sync (full release June 2026) syncs only scripts; models, UI, and everything else stay binary.

**The rule this teaches: read the community-tooling shelf as the engine's missing-features list.** Rojo means files-on-disk was missing. Wally means packages were missing. Tarmac means an asset pipeline was missing. Lune and run-in-roblox mean a headless engine was missing. Mantle means deploy automation was missing. When Spectra's community starts building a tool like these, treat it as a P1 bug report against the engine.

**Spectra's stance, mostly already secured.**
- The map is text (JSON), the single authored artifact, with zero derived data, byte-identical through save/load/save, and unknown members preserved (P2, pinned). It diffs, merges, and reviews in any git host with no sync layer.
- Assets are real files under `Assets/`, loaded from disk, never embedded, never uploaded anywhere, never moderated by anyone (existing content rule and pillar). Retroactive muting of a shipped game is not a policy Spectra declines to enact; it is structurally impossible, because Spectra never holds the assets.
- The engine is a library with a headless simulation path (the logic/rendering separation pillar: simulation runs with no camera, input manager, or renderer). The test suites already run the full CSG/scene/editing stack against a `FakeRenderer` in ordinary CI. This must remain true of every future system, networking included.
- Binary formats are derived build outputs only, never authored artifacts (P11b was superseded for exactly this reason).
- **New commitments this document adds:** the editor must never require an account, a network connection, or an auto-update to function; editor versions are side-by-side installable; a package/dependency story for Luau content is deliberately deferred but owed (record it against the scripting arc, and ship it first-party when Luau content sharing becomes real).

## 2. Engine ceilings: shaders, quality, caps, and the weakest phone

**What professionals say.** The most-liked engine request of all: no custom shaders, none, with the "Material graph based custom shaders" thread open since February 2019 and GPU programmability still officially "research stage" as of 2024. The client's graphics-quality slider silently overrides developer intent (shrinks the far plane under snipers, culls lights, degrades water) with no API to even read the effective level. Lighting is one fixed engine with hard-coded constants; the request to raise the 60-stud point-light range ran eight years before Roblox doubled it in 2025. Hard upload caps (about 20k triangles per mesh; 1024px textures until 4K arrived January 2026) force artists to split models and eat visible seams. Physics is a black box that throttles under load with no override (World // Zero and Toilet Tower Defense both rewrote NPC systems around it) and guarantees no determinism. Servers are opaque: unknown hardware, undisclosed specs since 2018, no provisioning control. Native code is categorically banned; Luau is the ceiling, and heavy-simulation teams document "reduce scope" as the official workaround. Above all of it: every capability is sized for the weakest supported phone, developers cannot declare a higher hardware floor, and Roblox confirms on record that high-end features wait until the mobile gap closes. And there is no version pinning: the engine updates weekly under shipped games, with 2025-2026 examples of live games breaking (custom rigs, MessagingService, Highlight rendering) and no rollback but a bug report.

**Spectra's stance.**
- User-authored shaders are already first-class: SpectraShade is the engine's own shading path, shaders are real files, hot-reloaded, cross-compiled per backend. The engine's shaders and a game's shaders are the same kind of thing (law 1). The gap to close is authoring-side (S2, S3 parameter scopes and manifests), not a capability wall.
- Quality scaling is developer-owned policy over engine-provided mechanism. Spectra may ship auto-quality heuristics; they must be opt-in, enumerable, readable at runtime, and overridable per game. The engine never silently rewrites what a game asked to render. This inherits the existing house rule: **nothing degrades silently** (the part-brush overlays disclose their caps; `InertPartBrushCount` counts instead of throwing; `ScaleGizmo` reports its proportional fallback). Elevate that rule from culture to contract for every future scaling system: LOD, streaming, physics load-shedding all report what they did.
- No artificial content caps. Limits exist where hardware imposes them, are stated in units the developer can measure, and are per-game tunable where the trade is real (the demo's `--parts` and `--size` sweeps are the pattern: the engine helps you measure your budget instead of imposing one).
- The hardware floor is the developer's choice. Spectra targets what the game targets; an integrated-GPU-friendly path exists because it was measured (`docs/performance.md`), not because every game is clamped to it.
- Determinism and steppability are design inputs, not afterthoughts: the mover is a pure function over state and command; the fixed tick is explicit; physics stepping is owned by the engine loop, not hidden. The honest open question (Box3D world snapshot/restore, `physics.md` Y13) stays named rather than assumed away.
- Version pinning is the contract (law 2): a shipped Spectra game embeds its engine; nothing updates it but its developer. This is automatic for an engine you link rather than a platform you run inside, and it must stay true if a hosted runtime ever exists.
- The two-language cliff exists here too (Luau, then C#), but it leads somewhere: outgrowing Luau means extending the engine you already have source for, not a categorical ban. Document the cliff honestly (as `roblox-onboarding.md` 2.4 already does) and keep the native seam real.

## 3. Netcode: why competitive genres run compromised or not at all

**What professionals say.** The verdict, in their own words: "Any game with competitive aspects is completely compromised in its integrity by the state of Roblox security" (Arch_Mage, Deepwoken). Characters were client-authoritative for the platform's whole life; the 2019 "Server Authoritative Movement" request sat unanswered while a veteran built Chickynoid, a full replacement character controller with prediction and rollback, from userland. Roblox's own Server Authority shipped in 2026, opt-in, and requires rearchitecting the game around a new input system: the cost of retrofitting authority a decade late. There is no lag compensation, rewind, or history buffer; every shooter either trusts the client (exploitable) or raycasts stale server state (punishes latency). Replication runs at a hard-coded 15-20 Hz nobody can change (a developer showed an internal flag fixes it, i.e. the capability is withheld). Replication semantics and bandwidth budgets are undocumented; the community's canonical reference is reverse-engineered folklore that contradicts official docs. Until Nov 2023 the only transport was reliable-ordered (the worst semantics for state); unreliable remotes arrived capped at ~900 bytes with no sequencing, priorities, or flush control. Exploiting ran at industrial scale (Deepwoken: 60,000 detected exploiters in four months, 8% of paying customers; BedWars: tens of thousands per 72 hours) until Hyperion raised the bar in 2023, and aim/ESP cheats remain structurally unbeatable because the platform gives developers no anti-cheat hooks at all. Rollback netcode for fighting games is impossible in principle: no peer transport, no determinism, no manual stepping; the one credible attempt bypassed the entire engine and still ate relay latency. Vehicles are janky by construction under the network-ownership trilemma.

**Spectra's stance, sharpening the existing networking pillar.**
- **Server-authoritative simulation with client prediction is the default shape, designed in before any game exists to migrate.** The mover already has the right anatomy: `CharacterState` struct plus replayed `CharacterCommand` with absolute values is prediction and reconciliation waiting for a transport. The 2026 Server Authority episode is the proof of why this cannot be retrofitted politely.
- **Lag compensation is an engine primitive**: a bounded history ring of authoritative states with server-side rewind queries, not a per-game reinvention. The command log (already the replication log in the pillar) is the backbone.
- **Tick rate, send rate, and interpolation delay are developer-set numbers with documented defaults.** No withheld internal flags.
- **Replication semantics are documentation, not folklore** (the strongest cheap lesson in the whole research): exact channel guarantees, budgets, quantisation, and per-channel runtime telemetry ship with the feature. If a developer must reverse-engineer it, the feature is unfinished.
- **Transport offers reliable-ordered, unreliable, and unreliable-sequenced lanes from day one**, with visibility into flush timing. This costs little when designed in and cost Roblox a decade to bolt on.
- **Determinism budget:** the gameplay layer (mover, entity logic, command processing) stays deterministic and manually steppable so rollback-class netcode is buildable; the physics engine's determinism limits are documented per `physics.md` rather than discovered. P2P remains an open design question for the dedicated+P2P pillar; record it, do not assume it.
- **Anti-cheat is an architecture, not a product**: authority server-side by default, validation hooks where the engine already sees inputs and state, and no design that requires trusting the client for anything competitive. Aim-level cheating is unsolvable for everyone; what Spectra owes is that no *movement or state* cheat is possible by construction, and that developers get the hooks Roblox never gave.
- The first-person presentation gap from the FPS analysis lands here as a rendering item: a viewmodel path (own pass, own FOV, depth remap) is cheap now that render targets and passes exist; it belongs on the R arc so it is designed rather than faked with camera-parented meshes.

## 4. The scripting and object-model gap

**What professionals say.** The engine provides script containers and remotes but no application architecture; the community framework that filled the gap (Knit) was built, became the standard, and was archived in July 2024 by its own author, whose postmortem concedes the pattern was wrong and untypeable. There is no entity/component model: the Matter ECS docs state plainly that DataModel instances "cannot adequately represent complex game state" and Attributes are primitive-only, so serious teams ship their own ECS. BindableEvent is slow, leaky, and untypeable, so custom signal libraries are "the single most reinvented wheel in Roblox's history" (2026 engine request, unanswered). Event connections leak by default, spawning three generations of cleanup libraries (Maid, Janitor, Trove) whose whole purpose is remembering to disconnect. RemoteEvents are untyped and unvalidated, so teams compile schemas through Zap and ByteNet, an IDL layer the platform never shipped. TestEZ, Roblox's own test framework, was archived in 2024. Typing a metatable class takes documented incantations (`typeof(setmetatable(...))`) that the most-cited guide's own author says hurt to write, and the revealed preference of serious teams was to transpile TypeScript (roblox-ts) to buy tooling the platform never provided.

**Spectra's stance** (this section condenses the standing design discussion; the entity arc P4 to P6 is where it lands).
- The entity model is the engine-provided unit of structure: declarable from Luau, visible to the editor, serialized in the map, with engine-owned lifecycle. When an entity dies, its connections, signals, and scheduled work die with it. That single guarantee deletes the cleanup-library genre.
- Signals and a single blessed class idiom ship in the Spectra Luau stdlib, constructible by user code (law 1), used uniformly by every sample and doc. Consistency, not syntax, is most of what Roblox's ecosystem lacks.
- The scripting API surface is exported as machine-readable schema (P5's generator), from which Luau definitions and `.d.ts` are generated. Typed networking falls out of the same schema: remotes are declared, validated, and quantised from declarations, not hand-guarded (the Zap lesson: ship the IDL).
- Testing is first-party and headless because the engine already is (section 1); the scripting layer inherits a runner, not an afterthought.
- Do not fork Luau for class syntax; track upstream (the new type solver landed platform-wide in 2026 and keeps closing the gap) and spend the effort on the object model instead.

## 5. Ground that shifts: governance lessons

**What professionals say.** The March 2022 audio change retroactively muted assets in enormous numbers of shipped games with about a week's notice (the canonical "ground shifted" incident; the 90-page announcement thread is still cited in 2026). Deprecations force-migrate: legacy chat was auto-converted with the replacement below feature parity. Automated moderation falsely terminates developer accounts in waves (the January 2026 IP-linking wave: 150+ appeals answered with identical boilerplate), with games and businesses attached; hijacked games get support "only when a reporter contacted the company" (404 Media, 2026). The 2024 Terms update licensed already-uploaded creator content for AI training by default. Announcement threads absorb four thousand replies and change nothing. Critics meet lawyers (People Make Games, Ruben Sim, the 2025 Schlep case). Payout systems restructure overnight under businesses built on them.

**What an engine can and cannot take from this.** Spectra is an engine, not a platform operator; most of these behaviors are things Spectra structurally cannot do to anyone, and the commitment is to keep it that way: the engine never holds the developer's content, identity, or revenue, so it never has the leverage these incidents required (law 3). The residue that does bind now:
- Deprecations in the engine never rewrite authored content. A migration is a tool the developer runs, on a version they chose, with a diffable result (text formats make this reviewable).
- Format compatibility is contractual and asymmetric by design: old engines refuse newer maps loudly (`MinimumReadableMapVersion`), new engines read old maps forever, unknown data survives.
- If Spectra ever grows hosted services (the Realms direction, Team-Create-style collaboration, a content registry), this section becomes their constitution: no retroactive invalidation of published content, developer data exportable at all times, no capability that exists only as an opt-out, and communication that can actually change a decision. Write those into the service design docs on day one; Roblox demonstrates what accretes otherwise.

**The adjacent services carry the same lesson** (from the completeness sweep): Roblox's DataStores are rate-limited and lossy enough that a third-party save-system genre exists; GDPR deletion arrives as a bot message telling each developer to go delete keys manually; localization tooling has multi-year open bugs; mandatory text filtering false-positives on legitimate gameplay text; AI voice moderation issues unappealable platform-wide bans for saying "Minecraft"; analytics are delayed, coarse, and export-broken, so professional telemetry runs through third parties. The pattern for Spectra: a game's data is the developer's data, on the developer's storage, with the engine providing primitives (persistence, telemetry hooks) rather than mandatory managed services with opaque budgets.

## 6. Economics, lock-in, and reputation

Mostly outside an engine's scope, but three findings bind design.

- **The lock-in critique is the loudest professional dealbreaker** (about 25-28 cents of each player dollar reaching developers, no export path, audiences addressable only through Roblox; "the only exits are acquisition or abandonment"). Spectra's answer is structural and should be stated as a promise wherever the engine is described: a Spectra game is a standalone AOT binary the developer owns, assets are files, the map is text, and there is no platform between the developer and their players unless they choose one. Nothing needs an export feature because nothing is imprisoned.
- **The aesthetic and status ceiling ("a Roblox game" as a low-status category) is partly caused by the engine ceilings of section 2**: one lighting rig, no shaders, hard caps produce a recognizable look no title escapes. Capability ceilings become category stigma; avoiding the first avoids the second.
- **The audience and monetisation ethics critiques** (engagement-farming aimed at children, People Make Games' scrip analysis, the 2025-2026 legal actions) are about a platform operator's incentives, not an engine's. Spectra's only obligation is negative: no engine-level services whose economics reward those patterns, and no telemetry or monetisation primitives designed around them.
- One reputational finding is genuinely market-not-platform: Roblox-native developers outperform industry veterans *on Roblox* because live-ops instincts beat production pedigree there. That cuts both ways for Spectra's onboarding pillar: the target developer's skills are real, and the engine that treats them as professionals (this whole document) is the pitch.
